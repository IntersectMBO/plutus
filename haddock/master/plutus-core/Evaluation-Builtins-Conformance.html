data CheckMode Source #

How thoroughly a sampled case is checked against its property before it is written.

  • FastCheck evaluates the terms with the untyped CEK machine, as the exporter does to record results. It confirms that the reference implementation satisfies the property but does not typecheck the terms.
  • FullCheck uses evalTerm, exactly as the normal tests do: it typechecks the terms and evaluates them with a freshly built typed evaluator. That setup is repeated for every case, which makes it much slower.

data Check Source #

A property check expressed without performing it. Normal QuickCheck suites interpret it as an assertion, the Hedgehog suites have their own interpreter, and the test generator extracts its terms, first checking with checkHolds that the reference implementation satisfies the property for the sampled input.

checkHolds ∷ CheckMode → Check → Bool Source #

Whether the reference implementation satisfies a check. This mirrors the Testable instance, so the cases written out are those the normal tests would accept. With FullCheck the terms are evaluated, and typechecked, exactly as the normal tests do; with FastCheck they are evaluated by the untyped machine alone. A false precondition counts as satisfied, since such inputs are discarded rather than tested.

guardCheck ∷ CheckMode → Check → [TermCase] → [TermCase] Source #

Replace the terms of a check by a violation if the reference implementation does not satisfy it. Writing such a case would record behaviour that contradicts the property as if it were the expected result.

isCekSuccess ∷ TypeErrorOrCekResult → Bool Source #

evaluationFailureText ∷ Text Source #

Text recorded in .expected and .budget.expected files when evaluation fails. The conformance harness compares those files verbatim against its own shownEvaluationFailure; that constant lives in PlutusConformance.Common, which depends on this library, so it cannot be imported here. Keep them in step.

generateTermFiles ∷ OutputFormat → FilePath → Int → PropertyId → String → [TermCase] → IO Generated Source #

Consume at most the requested number of cases, writing each one as it is produced so that memory use does not grow with the number of cases. The count is a number of terms, not of sampled inputs: an equality check emits both terms under one number with -A/-B suffixes, while a check that combines several terms (for example CheckBoth) supplies one numbered case per term. Each term has its own result and budget files. A case that violates its property, or a stream with fewer cases than requested, is an error.

propertySeed ∷ QCGen → PropertyId → QCGen Source #

The random generator for one property, derived from the run's seed and the property's identifier. Using the seed directly for every property would give them all the same stream of random numbers, and so correlated inputs. Deriving it from the identifier also means that the cases generated for a property do not depend on which other properties are selected.

samplingSize ∷ Int Source #

Size passed to the generators when sampling inputs.
